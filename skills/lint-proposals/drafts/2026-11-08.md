## LP-1: Server data comes from api-queries, not inline query functions
**Status:** proposed · **First seen:** 2026-06-11 · **Evidence:** 3 from 2 people

- **Convention:** Components get server data by passing a query object from `@automattic/api-queries` to `useQuery()` / `useSuspenseQuery()`. They don't define a `queryFn` inline.
- **Evidence:** [#113643](https://github.com/Automattic/wp-calypso/pull/113643#pullrequestreview-4989724489), [#112167](https://github.com/Automattic/wp-calypso/pull/112167#discussion_r3510204737), [#109357](https://github.com/Automattic/wp-calypso/pull/109357#discussion_r3056441695) ([2nd](https://github.com/Automattic/wp-calypso/pull/109357#discussion_r3056401756))
- **Violations on trunk:** 2 in 2 files (as of 2026-11-08). Both are the auth bootstrap (`app/auth/index.tsx`, `app/omnibar/user.ts`) and would be listed under `ignores`. The rule mainly keeps it that way.
- **Draft rule:**
  ```js
  {
  	selector:
  		"CallExpression[callee.name=/^use(Suspense|Infinite|SuspenseInfinite)?Query$/] > ObjectExpression > Property[key.name='queryFn']",
  	message:
  		'Define the query in @automattic/api-queries and pass the query object, e.g. useQuery( siteQuery( siteId ) ). Inline queryFn bypasses shared caching and invalidation.',
  },
  ```
- **Rule PR:** —
- **Decision:** —

## LP-2: Don't branch on which dashboard app is running
**Status:** proposed · **First seen:** 2026-01-28 · **Evidence:** 4 from 3 people

- **Convention:** Outside the app setup code, don't compare the current dashboard to `'ciab'`, `'dotcom'` or `'a4a'`. Put the difference in the app config (`AppContext`) or in the app's translation overrides.
- **Evidence:** [#109716](https://github.com/Automattic/wp-calypso/pull/109716#discussion_r3025550032), [#109345](https://github.com/Automattic/wp-calypso/pull/109345#discussion_r2950503502), [#108783](https://github.com/Automattic/wp-calypso/pull/108783#discussion_r2825699600), [#108277](https://github.com/Automattic/wp-calypso/pull/108277#discussion_r2752938104)
- **Violations on trunk:** 0 outside `app-*/`, `app/routing.ts` and `utils/link.ts` (as of 2026-11-08). The rule would lock in the current state.
- **Draft rule:** (with `ignores` for `app-*/**`, `app/routing.ts` and `utils/link.ts`)
  ```js
  {
  	selector: "BinaryExpression[operator=/^[!=]==$/] > Literal[value=/^(ciab|dotcom|a4a)$/]",
  	message:
  		'Don’t branch on which dashboard is running. Add a field to the app config (AppContext), or put copy differences in the app’s translations (e.g. app-ciab/translations.ts).',
  },
  ```

- **Decision:** —

## LP-3: Root-relative links to WordPress.com pages go through wpcomLink()
**Status:** proposed · **First seen:** 2025-12-04 · **Evidence:** 4 from 2 people

- **Convention:** A link to a WordPress.com/Calypso page (`/me/…`, `/purchases/…`) is wrapped in `wpcomLink()`. A bare root-relative `href` breaks on calypso.live and in development.
- **Evidence:** [#112500](https://github.com/Automattic/wp-calypso/pull/112500#pullrequestreview-4681593063), [#107916](https://github.com/Automattic/wp-calypso/pull/107916#discussion_r2660218055), [#107402](https://github.com/Automattic/wp-calypso/pull/107402#discussion_r2587241389), sweep [#107792](https://github.com/Automattic/wp-calypso/pull/107792) (wrapped people URLs, no rule added)
- **Violations on trunk:** 5 in 4 files (as of 2026-11-08). 2 are inside `isDashboardBackport()` branches, where relative links are intended (`ssh-card.tsx`, `site-delete-modal/index.tsx`). They'd need an inline disable, so the rule has a known false-positive case. Likely real: `jetpack-site-disconnect/index.tsx` (2), `overview-plan-card/index.tsx` (1).
- **Draft rule:**
  ```js
  {
  	selector: [
  		"JSXAttribute[name.name='href'] > Literal[value=/^\\//]",
  		"JSXAttribute[name.name='href'] > JSXExpressionContainer > Literal[value=/^\\//]",
  		"JSXAttribute[name.name='href'] > JSXExpressionContainer > TemplateLiteral > TemplateElement:first-child[value.raw=/^\\//]",
  	].join( ', ' ),
  	message:
  		'Root-relative hrefs break on calypso.live and in development. Wrap WordPress.com paths in wpcomLink(), or use the router’s Link for dashboard routes.',
  },
  ```
- **Rule PR:** —
- **Decision:** —

## LP-4: Tests mock the HTTP API, not dashboard modules
**Status:** proposed · **First seen:** 2026-02-12 · **Evidence:** 7 from 3 people

- **Convention:** Dashboard tests stub network calls with `nock` (and the `test-utils` helpers). They don't `jest.mock()` the dashboard's own modules or `@automattic/api-queries` / `api-core`. Mocking those ties the test to implementation details.
- **Evidence:** [#113762](https://github.com/Automattic/wp-calypso/pull/113762#discussion_r3840543562), [#109881](https://github.com/Automattic/wp-calypso/pull/109881#discussion_r3055196040), [#109742](https://github.com/Automattic/wp-calypso/pull/109742#discussion_r3032019797), [#108643](https://github.com/Automattic/wp-calypso/pull/108643#discussion_r2791643644), [#108641](https://github.com/Automattic/wp-calypso/pull/108641#discussion_r2792701097), sweeps [#111112](https://github.com/Automattic/wp-calypso/pull/111112) and [#108971](https://github.com/Automattic/wp-calypso/pull/108971) (removed mocks, no rule added)
- **Violations on trunk:** 97 in 68 test files (as of 2026-11-08). Too many to fix before turning the rule on. Start at `warn`, or turn it on as `error` with ESLint's bulk suppressions (`eslint --suppress-rule no-restricted-syntax`), so only new mocks fail.
- **Draft rule:** (test files only)
  ```js
  {
  	selector:
  		"CallExpression[callee.object.name='jest'][callee.property.name='mock'] > Literal:first-child[value=/^(\\.\\.?\\/|@automattic\\/api-(queries|core))/]",
  	message:
  		'Stub the HTTP request with nock (see test-utils) instead of mocking dashboard modules. See .claude/rules/dashboard-testing.md.',
  },
  ```

- **Decision:** —

## LP-5: Preloaded route data is read with useSuspenseQuery
**Status:** not lintable · **First seen:** 2025-12-16 · **Evidence:** 3 from 3 people

- **Convention:** If a route's loader preloads a query (`ensureQueryData`), the component reads it with `useSuspenseQuery()`. A `useSuspenseQuery()` without a matching preload shows the wrong loading state.
- **Evidence:** [#114467](https://github.com/Automattic/wp-calypso/pull/114467#discussion_r4058280235), [#107830](https://github.com/Automattic/wp-calypso/pull/107830#discussion_r2642152622) ([2nd](https://github.com/Automattic/wp-calypso/pull/107830#discussion_r2642080728)), [#107709](https://github.com/Automattic/wp-calypso/pull/107709#pullrequestreview-3585808330)
- **Why not lintable:** the loader and the component live in different files, so a single-file rule can't connect them. Better suited to a benchmark pattern task, or the dashboard's `AGENTS.md`.

## LP-6: Prefer core components over one-off custom CSS
**Status:** not lintable · **First seen:** 2025-12-18 · **Evidence:** 4 from 2 people

- **Convention:** Use what `@wordpress/components` and the dashboard components already provide before adding custom CSS. If a component's layout is wrong, fix it in the component, not at the call site.
- **Evidence:** [#112962](https://github.com/Automattic/wp-calypso/pull/112962#pullrequestreview-5014485509), [#109805](https://github.com/Automattic/wp-calypso/pull/109805#discussion_r3060772671) ([2nd](https://github.com/Automattic/wp-calypso/pull/109805#discussion_r3042294553)), [#108989](https://github.com/Automattic/wp-calypso/pull/108989#discussion_r2881740722), [#107662](https://github.com/Automattic/wp-calypso/pull/107662#pullrequestreview-3572290280)
